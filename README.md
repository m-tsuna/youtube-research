# YouTube 発信リサーチ（youtube-research）

YouTube Data API を使って、キーワードで**最近6か月以内**に投稿された動画を探し、**本当の再生回数の多い順**に表示する Python プログラムです。
自分が動画を発信するときの参考リサーチに使います。
（AIエンジニア講座 課題8：連携した API に機能を追加。前の課題の [youtube-search](https://github.com/m-tsuna/youtube-search) をもとに作りました）

## 何をするものか

- **ショート動画だけ**に絞ることもできます（「すべて／ショートだけ」を選ぶ）
- **バズ度**（再生回数 ÷ チャンネル登録者数）を表示します。1倍を超える動画は、登録者以外にも広く見られた動画です。
  小さいチャンネルなのにバズ度が高い動画は、企画や編集の力で伸びた動画なので、まねする参考になります
- 結果を **CSV**（Excel や Google スプレッドシートで開ける表）に保存できます。いいね率・タグ・サムネイル URL も入るので、
  スプレッドシートでバズ度の順に並べ替える、伸びている動画のタグを調べる、といった使い方ができます

## 仕組み

1回の検索で、YouTube Data API を3つ順番に使います。

| 順番 | API | やっていること |
|---|---|---|
| 1 | `search.list` | 6か月以内（`publishedAfter`）の、再生回数の多い動画を候補として50本集める |
| 2 | `videos.list` | 50本の本当の再生回数・いいね数・長さ・タグ・サムネイルを取る |
| 3 | `channels.list` | 動画を出したチャンネルの登録者数を取る（バズ度の計算に使う） |

`search.list` の再生回数順（`order=viewCount`）は順番が正確でないので、`videos.list` の本当の再生回数で並べ直しています。

## 事前準備

### 1. ライブラリのインストール

```bash
pip install google-api-python-client python-dotenv
```

### 2. Google Cloud Console の設定

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを選ぶ（なければ作る）
2. 「API とサービス」→「ライブラリ」で **YouTube Data API v3** を検索して「有効にする」
3. 「API とサービス」→「認証情報」→「認証情報を作成」→「API キー」でキーを作る
4. 作ったキーの編集画面で「API の制限」→「キーを制限」→ **YouTube Data API v3** だけにチェックして保存する

公開されている動画を検索するだけなので、ログイン（OAuth）は使いません。

## 秘密ファイルの用意の仕方

API キーは GitHub に載せていません（`.gitignore` で除外）。自分で用意してください。

| ファイル | 中身 | 用意の仕方 |
|---|---|---|
| `.env` | YouTube Data API の API キー | `.env.example` をコピーして `.env` という名前にし、`YOUTUBE_API_KEY=` の後ろに上で作ったキーを書く |

## 使い方

```bash
python main.py
```

- キーワードを入力し、動画の種類を番号で選びます（Enter だけなら「すべて」）
- 表示のあと、CSV に保存するか聞かれます。保存先は `results/` フォルダで、毎回新しいファイルになります
- 期間（6か月）・表示件数（10件）・ショートの長さの基準（180秒）は、`main.py` の先頭の設定で変えられます
- 途中でやめたいときは Ctrl + C を押してください

### CSV の列

順位、タイトル、チャンネル名、登録者数、再生回数、バズ度、いいね数、いいね率（%）、長さ（秒）、投稿日、タグ、サムネイルURL、動画URL、検索キーワード、種類、検索日

- 数の列は数字のまま入っているので、表計算で並べ替え・計算ができます。非公開の値は空欄です
- 文字コードは UTF-8（BOM 付き）なので、Mac の Excel で開いても文字化けしません

## 気をつけること（API の限界）

- **ショート動画の判定**：YouTube Data API には「ショート動画だけ」という指定がありません。
  そこで、次の2段階で判定しています
  1. 長さが3分以内（ショート動画の最長）の動画を候補にする
  2. `youtube.com/shorts/動画ID` のページを開いて、ふつうの動画のページ（`/watch?v=`）に転送されないものだけをショート動画とする。
     3分以内の横長の動画（企業の広告動画など）は、ここで除かれます
  - 2 は API ではなく YouTube のページの動きを使っているので、YouTube の仕組みが変わると使えなくなることがあります
- **登録者数はおおよその値**：YouTube は登録者数を上から3けたに丸めて返します（12,345人 → 12,300人）。なのでバズ度もおおよその値です
- 候補は検索で集めた50本の中から選ぶので、「6か月以内の全動画の中の再生回数トップ10」とは限りません

## 使える回数（割り当て）

- YouTube Data API は、1日に使える量（既定で 10,000 ユニット）が決まっています。無料です
- 1回の検索で 102 ユニット（検索 100 ＋ 動画の情報 1 ＋ チャンネルの情報 1）なので、**1日に約98回**まで検索できます
- 割り当ては毎日、太平洋時間の0時（日本時間の16時か17時）にリセットされます

## うまくいかないとき

| 表示 | 対処 |
|---|---|
| API キーが設定されていません | `.env` を作り、`YOUTUBE_API_KEY=` の後ろにキーを書く |
| API キーが正しくありません | `.env` のキーが Google Cloud Console のキーと同じか確かめる |
| YouTube Data API を使う許可がありません | YouTube Data API v3 を有効にする。API キーの制限に YouTube Data API v3 が入っているか確かめる |
| 今日の検索できる回数を使い切りました | 翌日のリセットを待つ |
| YouTube につながりませんでした | インターネット接続を確かめる |
| CSV を保存できませんでした | `results/` フォルダに書き込めるか確かめる |

詳しい仕様は [要件定義書.md](要件定義書.md) を見てください。
